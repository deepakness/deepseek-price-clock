# DeepSeek Price Clock (macOS) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A macOS menu-bar app that ports the existing browser extension: whale glyph green for off-peak / red for peak, click for a panel with countdown, 24-hour timeline, price windows, and current rates.

**Architecture:** A SwiftPM package under `macos/` with a dependency-free core library (`PriceClockCore`: peak/off-peak logic, rate table, label formatting), a SwiftUI executable (`DeepSeekPriceClock`: `MenuBarExtra` + panel, notifications, settings), and a test target whose fixtures are generated by running the real `price.js` in a node `vm`. A `build.sh` assembles the `.app` bundle and signs it with a stable self-signed identity.

**Tech Stack:** Swift 6.3 / Xcode 27, SwiftUI `MenuBarExtra`, `Observation`, `UserNotifications`, `ServiceManagement`, Foundation only. Node (for fixture generation), `codesign`, `zip` not needed.

**Spec:** `docs/superpowers/specs/2026-11-15-macos-menubar-app-design.md`

## Global Constraints

- Minimum OS: macOS 14.0 (`LSMinimumSystemVersion` 14.0, `platforms: [.macOS(.v14)]`).
- Bundle identifier: `com.deepakness.deepseek-price-clock`. Executable name `DeepSeekPriceClock`, module names have no spaces.
- Signing: self-signed Code Signing certificate named `DeepSeek Price Clock Dev` (created once in Keychain Access; documented in the README). No ad-hoc signing.
- Everything new lives under `macos/`. `manifest.json`, `price.js`, `background.js`, `popup.*`, `icons/`, `build.mjs`, `RUNTIME_FILES`, and `platforms/` must stay untouched, and `node build.mjs` must still produce identical extension output.
- No runtime dependencies, no network calls, no host permissions: Foundation + system frameworks only.
- Price values ported verbatim: V4.1 Flash `$0.15 / $0.003 / $0.60` off-peak, `$0.30 / $0.006 / $1.20` peak; V4 Pro `$0.66 / $0.022 / $1.98` off, `$1.32 / $0.044 / $3.96` peak (input / cached input / output, per 1M tokens).
- Logic constants ported verbatim: `SWITCH_MINUTES = [60, 240, 360, 600]`, `WEEKEND_RULE_START = 1787414400000` ms (2026-08-22T16:00:00Z), `CN_HOLIDAYS = [("2026-09-25","2026-09-27"), ("2026-10-01","2026-10-07")]`.
- Copy ported verbatim from `background.js`: titles "DeepSeek: peak pricing started" / "DeepSeek: off-peak started (half price)"; messages "Off-peak again <time>" / "Half price until <time>"; tooltip "DeepSeek: peak pricing until <time>" / "DeepSeek: off-peak (half price) until <time>".
- Minus sign in `GMT±N` labels is U+2212 `−`, as in `popup.js`.
- Commit messages: short imperative, matching repo style.

## Review Focus

Uncovered failure modes most likely to bite a user, each pinned by a step in the task that owns the code:

1. **Clock/timezone changes while running** (travel, NTP jump, DST): panel labels and icon must follow within one tick, no crash. → Task 6, manual step.
2. **Wake from sleep across a switch**: icon correct within a second, and no late notification for a flip older than 5 minutes. → Task 8, grace-window unit test + manual step.
3. **Switch second with the panel open**: countdown and phase must flip without closing the panel. → Task 7, manual step at a switch minute.
4. **Weekend/holiday all-off-peak day**: timeline collapses to a single bar; window row shows one long window, never a zero-width segment. → Task 3 unit test (`displaySegments` on 2026-11-15 → one segment `0…1440`), Task 7 manual step.
5. **Notification permission denied, then re-toggled**: toggle reflects real authorization rather than a stuck-on switch. → Task 8, manual step.

- [ ] **Step 5: Implement `PriceClock.swift` (constants + gate + phase)**

Signature and exact behaviour; body follows `price.js` mechanically:

```swift
public enum Phase: String, Codable, Sendable { case peak, off }

public enum PriceClock {
  public static let switchMinutes = [60, 240, 360, 600]
  public static let weekendRuleStart = Date(timeIntervalSince1970: 1_787_414_400)
  public static let cnHolidays: [(from: String, to: String)] = [
    ("2026-09-25", "2026-09-27"), ("2026-10-01", "2026-10-07"),
  ]

  public static func offPeakAllDay(_ date: Date) -> Bool
  public static func phase(at date: Date) -> Phase
}
```

Implementation notes that are not mechanical: Beijing weekday and Beijing date key come from a **fixed +8h shift** on the instant (`isBeijingWeekend`, `beijingDateKey`), never from `TimeZone.current`; the date key is formatted with a `DateFormatter` whose `timeZone` is UTC and `locale` is `en_US_POSIX`, format `yyyy-MM-dd`. `offPeakAllDay` is `date >= weekendRuleStart && (isBeijingWeekend || isBeijingHoliday)`. `phase` is `off` when `offPeakAllDay`, otherwise `peak` for UTC minute-of-day in `[60, 240)` or `[360, 600)`, else `off`. `minuteOfDay` is derived from `date.timeIntervalSince1970` arithmetic (integer division by 60, mod 1440), not `Calendar`.

- [ ] **Step 1: Add the `--segments` mode to the generator**

When invoked as `node Tools/gen-vectors.mjs --segments <offset>`, generate samples at the top of every 4th hour across the range `1785542400000 ..< 1801440000000` and write/merge into `segments.json` the `displaySegments(new Date(t), offset)` result. The default (no-argument) run must spawn one child per offset with a pinned `TZ` so node's local date equals the display offset:

| offset | TZ |
|---|---|
| `0` | `UTC` |
| `480` | `Asia/Shanghai` |
| `-300` | `Etc/GMT+5` |
| `345` | `Asia/Kathmandu` |

Spawn with `execFileSync(process.execPath, [fileURLToPath(import.meta.url), "--segments", String(offset)], { env: { ...process.env, TZ }, stdio: "inherit" })`.

Rationale: `price.js` derives `dayStart` from the machine's *local* date, so the JS and Swift only agree when the pinned zone's offset equals the passed offset. The Swift side uses the closed form `dayStart = floorToUTCDay(date + offset*60) - offset*60`, which is what the JS computes when those agree.
